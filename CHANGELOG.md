# История изменений

## Levik Game: игра не остаётся без сети при сбое игрового канала — 2026-10-17

- Исправлено: VALORANT каждую секунду открывает новые соединения для замера пинга до регионов Riot. Они быстро занимали все места в игровом канале, и соединение самого матча отклонялось: игрока выкидывало при входе в матч. Теперь место освобождает самое давно молчащее соединение, а соединение матча никогда не вытесняется. То же исправлено на игровых узлах.
- Исправлено: если процесс, который передаёт игровые пакеты, завершался, игровой UDP продолжал уходить на закрытый локальный порт. Игру выкидывало из матча, а после этого она не запускалась (VAL 62) до переподключения VPN.
- Теперь, если этот процесс не удаётся восстановить, игра автоматически переходит на обычный VPN, и это видно в разделе Game.
- Ошибки этого процесса больше не завершают его, а записываются в журнал диагностики вместе с причиной.
- Журнал больше не заполняют служебные строки ядра о каждом соединении, а повторяющиеся ошибки пишутся один раз в 10 секунд. События Game в журнале сохраняются.

## Levik Game: история матчей — 2026-10-17

- В разделе Game появился блок «Последние матчи»: показываются 10 последних игровых сессий с датой, длительностью и регионом сервера.
- Для каждой сессии показываются средний, минимальный и p95 пинг (оценка сети до сервера игры), разброс, процент и число потерянных ответов, отправленные и полученные пакеты, а также пакеты, спасённые копиями и избыточным кодом.
- Видно, какой сервер первым доставил больше всего пакетов, с долей каждого пути.
- История хранится только на этом компьютере, без IP-адресов серверов игры. Матч, прерванный отключением VPN, тоже сохраняется.

## Levik Game: вход в VALORANT без VAL 62 — 2026-10-17

- Исправлено: VALORANT мог не входить с ошибкой VAL 62. TCP игры (вход, лобби, подбор матча) шёл через игровой узел, который отвечал на замеры, но не открывал новые соединения.
- TCP игры теперь идёт через обычный VPN, тем же путём, что и Riot Client. Через игровые узлы идёт только игровой UDP — трафик самого матча.
- Если игровой канал не прошёл проверку, игровой UDP тоже идёт через обычный VPN, а не через один непроверенный узел.
- Без доступа к игровым узлам включённый режим Game больше не блокирует выбранные игры: они идут через обычный VPN.

## Levik Game: игра всегда запускается — 2026-10-17

- Исправлено: игры (например, VALORANT) могли не запускаться с ошибкой «нет соединения». Стартовая проверка игрового UDP отправляла крупные DNS-запросы, которые публичные резолверы с части игровых узлов молча отбрасывают; после неудачной проверки весь трафик игры блокировался.
- Проверка теперь использует обычные DNS-запросы, и достаточно одного ответившего резолвера. Вход, лобби и подбор матча не ждут проверки UDP.
- Если многопутевой канал не прошёл проверку, игра идёт через лучший игровой узел без резервных копий; если игровые узлы не отвечают — через обычный VPN. Режим виден в разделе Game.
- Игра, запущенная после простоя, сразу использует проверенные пути: они больше не перестраиваются все разом в первую секунду игры, и первые пакеты не теряются. Сессия на игровом узле больше не истекает в простое.

## Права администратора и конфликты с другими VPN — 2026-10-16

- Если Levik VPN запущен без прав администратора, приложение сразу говорит об этом и перезапускается с нужными правами одной кнопкой.
- Перед подключением и после неудачного запуска туннеля приложение ищет, что ему мешает: другие VPN-клиенты (v2rayN, Clash, Hiddify, AmneziaVPN, WireGuard, OpenVPN, WARP и другие), процессы на нужных портах, порты, зарезервированные Windows для Hyper-V, WSL или Docker, и ядро Levik VPN, оставшееся после сбоя.
- Список мешающих приложений виден на экране; закрыть их можно одной кнопкой. Системные службы Windows приложение не трогает.

## Multipath: совместимость с игровым UDP — 2026-10-15

- Исправлена обработка XUDP между Xray и Multipath: игровые пакеты больше не отбрасываются из-за несовместимого формата.
- Проверяются до восьми подключений Game Squad: до четырёх быстрых путей передают копии, остальные остаются резервом. Оборванные пути восстанавливаются автоматически.
- Перед включением проверяется передача UDP через Multipath; при неудаче используется проверенный одиночный игровой маршрут.
- В диагностике видны отправленные пакеты, активные и резервные пути. Несколько подключений к одному узлу не означают несколько независимых серверов.

## Levik Game — 2026-10-15

- Отдельный раздел Game для подписок с доступом к Game Squad: 12 готовых профилей игр и добавление своего .exe.
- Выбранные игры идут через игровой сервер, остальные приложения сохраняют обычный VPN-маршрут.
- Автовыбор сравнивает реальные UDP-пробы через REALITY, Hysteria2 и TUIC по задержке, джиттеру и ответам; доступны ручной выбор и повторная проверка.
- Игровой маршрут закрепляется до переподключения. Замеры до контрольных DNS-серверов не заменяют пинг внутри матча.

## Отчёт для поддержки — 2026-10-10

- В «Поддержке» можно создать отчёт о проблеме: состояние подключения, сервер, настройки и последние записи журнала шифруются на компьютере и превращаются в одноразовую ссылку для чата поддержки. IP-адреса, сайты и данные аккаунта в отчёт не попадают.

## Статистика качества подключения — 2026-10-10

- Приложение может анонимно сообщать об обрывах и ошибках подключения, чтобы мы быстрее находили проблемные серверы и сети. IP-адреса, сайты и данные аккаунта не отправляются; при первом запуске приложение спрашивает согласие, отключить можно в настройках.
- Проверка туннеля различает причины сбоя: таймаут, ошибку TLS, сброс соединения, ответ прокси.
- Журнал диагностики сохраняется на диск с удалением IP-адресов, доменов и идентификаторов.

## Стабильность на компьютерах без IPv6 — 2026-10-09

## Подключение при недоступных сетевых классах WMI — 2026-10-01

- Определение сетевого интерфейса использует Windows IP Helper API напрямую, без PowerShell и WMI. Ошибка Windows «Недопустимый класс» (`0x80041010`) больше не блокирует этот этап подключения, если системные маршруты и физический адаптер доступны.
- Сохранены выбор по метрикам IPv4/IPv6, исключение виртуальных VPN-адаптеров и прежние резервные запросы.
- Добавлены регрессионные проверки отсутствующих WMI-классов и проверка нативного запроса и его JSON в Windows-сборке.

## Определение сетевого интерфейса Windows — 2026-10-01

- При сбое, таймауте или пустом ответе NetTCPIP приложение определяет физический адаптер с подключённым шлюзом резервным способом через Win32.
- Увеличено время ожидания ответа Windows и добавлены скрытые сетевые адаптеры при чтении активных маршрутов.
- Журнал показывает причину сбоя каждого способа и состояние адаптеров, чтобы отличать конфликт VPN от ошибки служб Windows или отсутствия подключения.
- Добавлены проверки резервного определения интерфейса и исполнения обоих PowerShell-запросов в Windows CI.

## Стабильность Windows — 2026-09-27

- Kill Switch сохраняет служебный DHCP/NDP-трафик для восстановления сети и проверяет полный набор своих обязательных фильтров.
- Исправлены гонки отключения и восстановления защиты; неудачная попытка восстановления больше не выключает дальнейший контроль.
- Исходная DNS-политика сохраняется до изменения и восстанавливается после перезапуска приложения; ошибки восстановления можно повторить без потери резервной копии.
- Остановка Xray ожидает фактического завершения процесса; убраны отложенные принудительные остановки уже завершённых процессов и устаревшие результаты статистики.
- Проверка конфигурации ядра имеет таймаут. При запуске проверка передачи трафика повторяется один раз без пересоздания туннеля.
- После неудачной смены сервера можно выбрать другой и сразу переподключиться, сохранив Kill Switch.
- Отключение доступно из трея при подключении, восстановлении и ошибке. Приложение сообщает об ошибке очистки сети перед выходом.
- Уведомления больше не показывают технический префикс Electron IPC; некорректный IPv4 DNS отклоняется до изменения соединения.
